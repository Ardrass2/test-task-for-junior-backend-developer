# Task Service

Сервис для управления задачами с HTTP API на Go. Поддерживает создание обычных и периодических (повторяющихся) задач.

## Требования

- Go `1.23+`
- Docker и Docker Compose

## Быстрый запуск через Docker Compose

```bash
docker compose up --build
```

После запуска сервис будет доступен по адресу `http://localhost:8080`.

Если `postgres` уже запускался ранее со старой схемой, пересоздай volume:

```bash
docker compose down -v
docker compose up --build
```

Причина в том, что SQL-файлы из `migrations/` монтируются в `docker-entrypoint-initdb.d` и применяются только при инициализации пустого data volume.

Базовый префикс API:

### Tasks (задачи)

- `POST /api/v1/tasks`
- `GET /api/v1/tasks`
- `GET /api/v1/tasks/{id}`
- `PUT /api/v1/tasks/{id}`
- `DELETE /api/v1/tasks/{id}`

### Periodic Tasks (периодические задачи)

- `POST /api/v1/periodic-tasks`
- `GET /api/v1/periodic-tasks`
- `GET /api/v1/periodic-tasks/{id}`
- `PUT /api/v1/periodic-tasks/{id}`
- `DELETE /api/v1/periodic-tasks/{id}`

## Периодические задачи

Периодическая задача — это шаблон, по которому система автоматически создаёт обычные задачи в трекере. Поддерживаются четыре типа периодичности:

| Тип | `recurrence_type` | `recurrence_params` | Описание |
|-----|-------------------|---------------------|----------|
| Ежедневная | `daily` | `{"interval": N}` | Каждый N-й день от `start_date` (1 = каждый день) |
| Ежемесячная | `monthly` | `{"day": D}` | Каждое D-е число месяца (1–30) |
| Конкретные даты | `specific_dates` | `{"dates": ["2026-04-10", ...]}` | Только на указанные даты |
| Чётные/нечётные | `even_odd` | `{"parity": "even"}` или `{"parity": "odd"}` | По чётным или нечётным числам месяца |

### Пример: создание ежедневной задачи

```bash
curl -X POST http://localhost:8080/api/v1/periodic-tasks \
  -H "Content-Type: application/json" \
  -d '{
    "title": "Обзвон пациентов",
    "description": "Ежедневный обзвон пациентов по списку",
    "recurrence_type": "daily",
    "recurrence_params": {"interval": 1},
    "start_date": "2026-04-07",
    "end_date": "2026-12-31"
  }'
```

### Пример: задача на чётные дни

```bash
curl -X POST http://localhost:8080/api/v1/periodic-tasks \
  -H "Content-Type: application/json" \
  -d '{
    "title": "Формирование отчётности",
    "description": "Подготовка ежедневных отчётов",
    "recurrence_type": "even_odd",
    "recurrence_params": {"parity": "even"},
    "start_date": "2026-04-01"
  }'
```

## Фоновый планировщик

Планировщик запускается вместе с приложением и каждую минуту проверяет, нужно ли создать задачи на текущую дату. Создание идемпотентно — повторный запуск не дублирует задачи благодаря уникальному индексу `(periodic_task_id, scheduled_date)`.

## Принятые предположения и проектные решения

1. **Периодическая задача — отдельная сущность.** Вместо добавления полей периодичности к существующей модели `Task` введена отдельная сущность `PeriodicTask` (шаблон). Это разделяет ответственность: шаблон описывает расписание, а сгенерированные задачи — конкретные экземпляры в трекере.

2. **Сгенерированные задачи — обычные задачи.** Они появляются в общем списке (`GET /api/v1/tasks`) и содержат ссылку на шаблон (`periodic_task_id`) и дату расписания (`scheduled_date`). Врач работает с ними как с обычными задачами.

3. **Идемпотентность генерации.** Уникальный индекс `(periodic_task_id, scheduled_date)` + `ON CONFLICT DO NOTHING` гарантируют, что задача создаётся ровно один раз на каждую дату для каждого шаблона.

4. **Генерация только на текущий день.** Планировщик создаёт задачи только на сегодняшнюю дату (UTC). Если сервер был недоступен, задачи за пропущенные дни не генерируются задним числом — для медицинского персонала прошедшие задачи теряют актуальность.

5. **Часовой пояс — UTC.** Все даты и время обрабатываются в UTC, как и в существующем коде.

6. **Ежемесячные задачи с day=30 в коротких месяцах.** Если у месяца нет 30-го числа (например, февраль) — задача в этом месяце просто не создаётся.

7. **Удаление шаблона.** При удалении `PeriodicTask` уже созданные задачи сохраняются (поле `periodic_task_id` становится `NULL`). Новые задачи перестают генерироваться.

8. **Деактивация без удаления.** Поле `is_active` позволяет приостановить генерацию без удаления шаблона.

9. **end_date опциональна.** Если не указана — шаблон действует бессрочно.

10. **start_date в будущем.** Задачи начнут создаваться только с указанной даты.
